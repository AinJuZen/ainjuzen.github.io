打开别人分享的工作流，右边红字：**缺失模型**。

点官方的「下载」——它直连 `huggingface.co`，转圈，然后没了。

我一开始以为是网速。后来把桌面版拆开数了一遍：

```
对 resources\app.asar（64 MB）做字符串统计：
    hf-mirror           0 处
    modelscope          0 处
    HF_ENDPOINT         0 处
    useChineseMirrors   136 处  ← 但它的标签是
                                 "Use Chinese Mirrors (Git & PyPI)"
```

**那个开关只管 Git 和 pip，不管模型文件。**

所以在国内网络下，模型下载这一块，官方是空的。

---

## 三条路，只有两条通

| 通道 | 走法 | 支不支持镜像 |
|---|---|---|
| 桌面版标题栏 Downloads | Electron 直连 huggingface.co | ❌ 没有开关 |
| Manager「模型」页 | Python 下载器 | ✅ 认 `HF_ENDPOINT` |
| 终端 `hf` | huggingface_hub | ✅ 认 |
| 迅雷 / aria2c | 你给它的直链 | ✅ 换个域名就行 |

**问题不是「没有镜像」，是「点了那个按钮走的是不通的那条」。**

---

## 于是做了这个

在「缺失模型」面板的同一个位置，加一个 **「镜像补缺」** 按钮：

```
扫出缺哪些文件
   ↓
按文件名去镜像反查官方仓库，优先 Comfy-Org/*
   ↓
断点续传下到 models/<type>/
```

**它不修改 ComfyUI 任何文件**——因为它是扩展，不是补丁。升级不碎。

---

## 两个反查上的坑，值得写下来

**① 不能用前缀当搜索词**

`qwen3vl_32b_minimax_h3_nvfp4_awq.safetensors` 这个文件，仓库叫 `MiniMax-H3`。
用前缀 `qwen3vl` 去搜，永远搜不到它。

**改成取所有相邻词对**——`minimax_h3` 出现在搜索词里，才搜得到。

**② 「搜到官方仓库就停」是个陷阱**

我当初写了个「已经有 Comfy-Org 的候选就不必再搜」的提前退出。
结果第一个关键词命中了**无关**的 Comfy-Org 仓库（Qwen），于是它再也不搜 `minimax`。

**四个文件全找不到，两个 bug 叠在一起。**

修完之后：35 秒 → 8-11 秒（关键词并行 + 仓库并行探测），四个文件全部命中。
